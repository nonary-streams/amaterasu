# Ordered audio extension route

The ordered audio route is opt-in trusted startup composition. It does not install a codec, prove a native implementation's claims, or establish client interoperability. The legacy Opus route remains the default and is retained as a separate session resource when an alternate route is prepared.

A session setting `audio_extension_route` selects one `codec` (`AC3` or `EAC3`) and four bounded service names: `encoder_control_service`, `encoder_service`, `capture_service`, and `transport_service`. The service names and typed contracts must also appear in the signed startup composition with the required provider and consumer grants and dependency order. The built-in audio provider exposes its ordered capture family only when its optional `ordered_service` is selected. The built-in media transport exposes its ordered family only when its optional `ordered_audio_service` is selected. Changing these startup settings is an explicit host configuration step; this document does not change installed settings.

The alternate encoder control service must support the ordinary caller-owned, idempotent `open`, `lookup`, and `close` lifecycle. Its open request includes `operation_id`, `codec`, `sample_rate`, `channels`, `channel_mask`, `frame_samples`, and `required_native_contract`; an allocated response supplies a nonzero `stream` and acknowledges the requested native contract. An open failure must not hide an allocation, and lookup by the same operation ID must resolve uncertain admission. The session retains the exact control service and attempted operation in its restart journal before open. Cleanup closes or reconciles the alternate encoder independently of the legacy encoder.

The native families are `amaterasu.audio-capture-ordered.native/2`, `amaterasu.audio-encoder-ordered.native/2`, and `amaterasu.audio-transport-ordered.native/2`. C definitions are in `sdk/include/amaterasu_media.h`; Rust consumers and providers bind them through `amaterasu_module_sdk::audio`. They are separate families, not resized legacy tables. A native module is trusted code; grants and interface identifiers are not a native-code sandbox.

Capture delivers a stream and generation with each borrowed PCM frame and an ordered speaker map. Each lane is one nonzero speaker bit; occupied lanes must be a permutation of the declared mask and unused entries must be zero. The encoder is configured against the exact capture stream, generation and lane order; it must reject layouts it cannot interpret. Never derive interleaved PCM lane order from the mask alone. Linux ordered capture obtains this map from the actual Pulse capture positions. Other capture implementations without an explicit verified order return unsupported.

Encoder enumeration returns immutable, bounded offers, each with a generation and ID, a complete output format and an explicit encoded channel order. `fixed_packet_bytes` is the exact plaintext access-unit length for that generation; zero means variable length. The built-in transport supports only fixed-size offers for 48 kHz stereo or 5.1 AC-3/E-AC-3-labelled complete 1536-sample units and rejects unsupported codec/framing/layout combinations. The encoder may receive shorter capture packets and must accumulate input as needed. It must preserve first-sample timestamps, retain rejected output for retry, and mark the next output unit after an accepted PCM discontinuity.

Before DESCRIBE, stream-session opens the alternate encoder without replacing Opus, copies one matching offer, binds the ordered capture and transport families, and asks the transport to probe the exact offer. Busy probes are retried within the prepare deadline. Only a successful chain is advertised. RTSP enables it only when the client echoes the exact offer; an absent or different acceptance retains Opus, and a matching acceptance with an unsupported channel layout fails. The selected offer is re-enumerated on the encoder binding before use and must still match its original generation, ID, format, lane order and size. The transport is prepared only after client acceptance and before any audio packet or cipher state is consumed. A changed or unsupported capture layout fails the selected route rather than silently falling back.

The pump copies bounded PCM and encoded bytes across synchronous native callbacks. A BUSY submission consumes neither the retained packet nor transport state; the pump retries the same immutable packet. Ordered audio transport checks source sequence and timestamp continuity, reserves queue capacity before modifying RTP/FEC/cipher state, and uses 32 ms RTP steps for contiguous units. A discontinuity retires any incomplete FEC group, skips the corresponding sequence/IV slots, and maps the next packet to its source-relative millisecond time; it does not combine shards across discontinuities. The transport encrypts before FEC when encryption is enabled and retains the existing explicit legacy-IV-wrap policy. EOS and teardown drain and retire the selected bindings and resources.

The tests use independently built synthetic AC-3- and E-AC-3-labelled encoders with marker bytes. They exercise capture ordering, selection, client negotiation, bounded retry, the production pump and transport, RTP/FEC and optional encryption. They do not implement Dolby encoding or demonstrate a real client, hardware or operating-system codec path.
