# Live feedback bootstrap and historical transition blocker

`b9b2cdac` closes the live-feedback profile at broker startup and validates the complete NVHTTP, stream and input lifecycle operation set, including pause, retirement and recovery lookups. It intentionally supersedes `43efeb40`'s activation behavior. No installed settings or permissions are changed.

A safe first-boot decision cannot be inferred from current State responses. `modules/state/src/store.rs::StateStore::open` creates a missing directory, and a missing namespace reads as an empty default; neither observation distinguishes a brand-new host from deleted or lost history. The pairing authority initializes `EffectGate` fenced with `startup_recovery_required=true` and no owner epoch. The stream owner's `feedback_retirement/restart.rs::Phase::Status` requires a pre-existing owner epoch, so it cannot bootstrap the new gate. The `5ee41526` qualification test manually created a stream endpoint and called `recover`; it did not demonstrate production startup.

Likewise, removing the old generic `effect_fence` and historical State selection leaves no current independent proof that old provider effects or workers are gone. `crates/contracts/src/lib.rs::RuntimeHostContext` in this baseline carries a State root and package information, not a host-attested first-boot generation or checked prior-worker retirement. `crates/host/src/supervisor.rs::WorkerProcess::drop` waits for its direct child during an orderly drop, but does not establish retirement after a supervisor crash or external-effect cleanup. A missing State key, an absent policy, a timer or a new process must not be treated as such proof.

The minimum missing production contract is a host-owned, authenticated bootstrap disposition that binds the selected State/host identity and selected stream/control provider incarnations, with either (a) a verifiably new protected host generation that has never admitted effects, or (b) checked retirement of all original owner/provider workers plus any required external cleanup. The host must retain the old profile selection while that evidence is unresolved. Pairing and the stream owner must consume the same disposition before a first `recover`; a lost reply must reconcile rather than invent another clean start. Tests need a real host + State + normal pairing/stream/control startup for clean bootstrap, missing/wiped history, crash, old worker still live, lost confirmation and unsupported profile removal. Until that owner-level proof exists, selecting the profile returns an explicit error.
