# NVHTTP feedback-source join

The optional source-join adapter connects an already paired NVHTTP session to the lifecycle and pairing authorities. Both NVHTTP and the built-in pairing provider deliberately reject production binding until the separate live revocation and retirement barrier is implemented and independently reviewed. The NVHTTP gate also prevents a replacement pairing provider from opening this path prematurely. This adapter does not itself enable an input or feedback route, grant a capability, prove client negotiation, or establish delivery.

Trusted startup composition may set `effect_source_join` to `{ "effect_owner": "<direct broker principal>", "input_consumer": "<selected lifecycle input principal>" }` and must also require session lifecycle. The setting defaults to absent. Any broker permissions needed by a deployment remain explicit; this source change does not modify installed grants. The selected effect owner is trusted native code and must construct its request from the authenticated stream's actual negotiated capability intersection, effective input policy, controller/device incarnation, and selected control transport. User-supplied capability names or source fields are not evidence of those facts. The stream-session production pipeline does not yet provide this assertion.

The selected direct owner may call `amaterasu.nvhttp/1` with `action: "bind_feedback_source"`, `authority_epoch`, the pairing SDK's `source` and `scope`, and the lifecycle input owner's `input_boot_epoch`. `amaterasu_module_sdk::nvhttp_source::BindFeedbackSource` constructs and submits this request without a parent, preserving direct broker identity. Broker caller and initiator must both equal the selected owner. There is one bounded in-flight join; additional requests fail closed.

NVHTTP looks up the canonical session and DER certificate using its private paired-launch record and verifies current View permission. It requests lifecycle's `resolve_effect_sources` with that canonical session target, then matches the exact source label and stream target, selected input principal, and input boot epoch. It rechecks the live NVHTTP session and current View permission around asynchronous calls, and submits `bind_stream` to the selected pairing authority with the private certificate and exact scope. Pairing independently checks its current certificate snapshot, selected per-capability View or Launch rule, and explicit client grant. A success reply contains only the authority epoch, source and scope, not the certificate.

The lifecycle query is a point-in-time observation. It does not fence a later lifecycle retirement, prove negotiated capabilities, or couple input-provider restarts to pairing. An uncertain binding admission or confirmation puts this NVHTTP adapter in `recovery_required` and refuses further joins for the process lifetime; restarting NVHTTP alone is not proof that a prior binding was retired. Before enabling pairing's production gate, implement the source-specific retire/reconcile path, protocol and effect-owner restart recovery, a synchronous pairing fence for lifecycle and host-configuration trust transitions, and real selected-provider final-effect and whole-control-stream drain tests. Do not treat a timeout or broker cancellation as evidence that a delivered bind did not occur.

The unit tests drive the adapter through a real broker with simulated lifecycle and pairing providers. They cover direct owner identity, exact source/session/generation/boot matching, revoked evidence, cancellation after bind submission and ambiguous pairing confirmation. They do not establish real-provider composition or hardware behavior.
