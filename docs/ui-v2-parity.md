# Vibeshine v2 UI parity work

Reference: the Vibeshine v2 frontend in `src_assets/common/assets/web`, inspected
at Vibeshine commit `874843c7b1c3b6aed27abc518d54aefa36993543`. Amaterasu's
console is independently built against its own management API. A visual match is
not evidence that a corresponding backend operation exists or works.

This is an implementation map, not a claim of completed parity. Recheck the
reference and the APIs as the work proceeds; retain scope checks, revision-bound
writes, and confirmation of ambiguous mutations.

| Vibeshine v2 | Amaterasu surface | Remaining work |
| --- | --- | --- |
| Shell and authentication | Sign-in and sidebar | Compare login/setup, navigation, responsive behavior, host status, and localization. Light, dark, and system appearance choices are present; new labels still need translations. |
| Overview | Host overview | Active stream counts come from the stream owner, refresh while visible, and remain independent of history-based pending-launch tracking and preference-controlled host vitals. Service access is shown separately; activity does not establish client delivery. Compare host identity, warnings, actions, and readiness. |
| Library and application | Library and inline application editor | Selection supports keyboard ranges and persists across pages at the same catalog revision. Cards expose contextual actions by pointer or keyboard, with focus restoration and outside dismissal. Search covers names, launch targets, and linked sources; search and sort are reflected in shareable links and restored from browser history. Existing Steam and Lutris artwork is displayed in the editor when accessible, with a fallback when unavailable; custom upload and cover search are not implemented. Desktop edits preserve its process-less launch. Global name sorting and sorting by known source scan a revision-bound compact index; records with no source metadata are grouped as Other, including provider entries whose provenance is unavailable. Complete provider sorting needs catalog provenance for entries without artwork or a Steam ID. Compare remaining context actions, editor navigation, dirty-state protection, and every supported application setting. |
| Devices and pairing | Host & devices; Settings > Devices | Client-name and identifier filtering preserves hidden drafts. Per-device removal uses revision-checked writes and readback; compare connection status, pairing, and per-client editors. Conflict review merges non-overlapping changes against the latest revision while preserving drafts; overlapping edits and unsupported values require review. Compare remaining v2 device controls and connection state. |
| Settings | Settings categories | Search matches field labels, hints, keys, sections, and categories across loaded editors while preserving the original forms; compare rich controls, category coverage, save/reload behavior, and platform-specific controls. Draft navigation protection is present for settings and application editors. |
| Statistics | Sessions and host metrics | Active streams come from a scoped stream-owner projection even when history recording is disabled. The browser derives rates from successive host counters and keeps a bounded local history; when recorded data is available, it loads retained samples within the configured limits and uses row identities to avoid duplicates. Active charts offer combined, live-only and recorded-only views. Combined charts append only live intervals that do not overlap the captured recorded history and visually separate the sources; current live rates remain visible independently. Host telemetry and stream data fail independently. Recorded sessions appear as cards; nearby matching sessions on the same page are grouped heuristically, with segmented charts, separate member controls and member-preserving export. Recent data appears first while retained snapshots load through bounded, pruning-aware pages; client delivery is not inferred. The browser caps a complete group or session load at 25,000 samples and 5,000 events and keeps the recent view if that limit is exceeded. Authorized operators can stop the current NVHTTP-managed launch and its associated application through owner-coordinated cleanup, guarded by an observed launch revision and followed by cleanup readback. Streams owned outside NVHTTP are not controlled by that action. Compare grouping across page boundaries and remaining v2 controls. |
| Logs | Diagnostics | The current host session has a scoped, bounded snapshot viewer with automatic incremental refresh, pause, follow-newest, full-snapshot search, severity filtering, match navigation, and download. New data is held while the user is searching, selecting text, or reading away from the end. A sanitized support bundle includes retained sessions in the current host log location, subject to file and byte limits; review before sharing. A separate caller-scoped journal supports search, copy, and export (up to 128 records). Compare log display and other v2 log sources; prior configured locations and separate helper logs are not included. |
| Integrations | Integrations, Steam, and Settings > Integrations | Provider cards show reported Steam, Lutris, and Playnite state; compare provider setup, synchronization, and remaining v2 integrations. |
| API tokens | API tokens | Administrator sessions with `tokens.manage` can create, search and revoke browser-issued scoped credentials. The secret is shown once, and tokens owned by native callers remain separate. Compare v2 route-level controls and legacy-token management; Amaterasu currently uses named scopes and does not expose native or legacy tokens here. |
| Maintenance | Maintenance, Plugins, Accounts, Settings | Administrator sessions can inspect and revoke other signed-in management sessions; account and package pages are linked. Device names and last activity are not recorded. Compare v2 update, recovery and support workflows against available Amaterasu operations. |
| Browser stream | No corresponding page | An H.264/Opus WebRTC transport foundation has a loopback Chromium decode and data-channel test; an owner-scoped UDP session driver is available for integration. Authenticated signaling, bounded remote input, capture and input ownership, host lifecycle integration, the browser workflow, and remote/client qualification remain unfinished; do not claim browser-stream parity. |

Validation must cover desktop and mobile, keyboard navigation, loading/empty/error
states, permissions, live form values and destructive actions, as well as the
frontend unit suite and signed-host browser qualification. Fixture rendering
alone does not qualify installed-service or client streaming behavior.
