# Hermes application-library audit

> Classification scope: read this audit with the [ecosystem plan](../application-library-ecosystem.md) and [boundary review](boundary-review.md). A generic API or core gap below describes the inspected current interfaces/composition. It does not require product behavior in the shell or a mandatory dependency on bundled Catalog, Launch, NVHTTP or transport. Library, protocol, networking and packet delivery implementations are intended to remain independently replaceable.

Audited 2026-10-31 against local Amaterasu `main` f8aa56337288632df64db1cca807dd3b0cd6beaa. Hermes primary sources below are moving `main` pages; an exact Hermes commit could not be verified from the accessible GitHub endpoint. This is a source/documentation comparison, not installation or live-stream verification. [Hermes](https://github.com/MrOz59/Hermes) identifies itself as an Apollo-derived Linux host compatible with Moonlight/Artemis/Hestia. A [community host list](https://www.reddit.com/r/MoonlightStreaming/comments/1ulw7t6/a_small_list_of_hosts_clients/) supplied discovery, not evidence of a popularity ranking.

- **Existing / importer work:** Hermes stores `apps.json` under `$XDG_CONFIG_HOME/hermes` or `~/.config/hermes` and documents copying the older Sunshine configuration on first start ([README](https://github.com/MrOz59/Hermes)). Its admin API exposes listing, saving, deleting and closing apps, plus cover upload ([API](https://github.com/MrOz59/Hermes/blob/main/docs/api.md)). An independent importer can read a selected source and translate supported metadata into authenticated staged provider snapshots, with stable source identities and removal only after a successful complete scan; current snapshot primitives are in `crates/module-sdk/src/application_library.rs:77` and `modules/catalog/src/protocol.rs:64`. Neither an actual Hermes importer nor conversion completeness has been established. Preserve or explicitly report unsupported source fields; do not overwrite the source or silently equate index with durable identity.
- **Existing / conditional:** Catalog entries have app-specific display output, virtual screen/mode/layout, structured config overrides, raw prep/undo/elevation, and output policy (`modules/catalog/src/model.rs:14`, `:28`, `:64`, `:83`). Existing launch handling includes ordered preparation, reverse undo, detached commands, working directory, process defaults, and desktop sessions (`modules/launch/README.md:50`, `:90`, `:119`). Hermes documents detached Steam Big Picture because its launcher self-updates, and a distinct Gamescope Steam entry with `mirror`, `exclusive`, or `extend` placement ([app examples](https://github.com/MrOz59/Hermes/blob/main/docs/app_examples.md)). Representable fields do not establish shell parsing, Steam reuse, compositor placement, exact exit semantics, or runtime parity; verify with real processes and displays.
- **Provider-implementable, with lifecycle obligations:** The SDK provider adapter separates discovery, artwork and lifecycle, and makes the provider responsible for actual effects and reconciliation (`crates/module-sdk/src/application_library/provider_adapter.rs:53`). Launch binds importer/service and checks identity before routing (`modules/launch/README.md:171`); provider start/lookup/stop/recover must deduplicate, fence delayed starts and provide matching retirement assertions (`crates/module-sdk/src/application_library/provider_lifecycle.rs:1`). A Hermes-specific provider can implement launching or importing where its effects can actually be fenced and observed. Native components are trusted; grants do not sandbox them. The supplied provider example is synthetic and is not evidence of real launch or restart cleanup (`docs/application-library-provider-configuration.md:4`, `:183`).
- **Generic API gap:** SDK discovery exposes only ID/name/optional opaque artwork (`crates/module-sdk/src/application_library.rs:267`), while catalog artwork references and routing admit only Steam/Lutris/Playnite (`modules/catalog/src/model.rs:94`, `modules/library/src/artwork.rs:10`). Generic discovery support therefore does not make imported Hermes covers available in `/applist`; the provider guide states this explicitly (`docs/application-library-provider-configuration.md:168`). Add authenticated provider-key + opaque reference + revision resolution, fixed configured routes, bounded contiguous pinned reads, and no arbitrary paths or service names. Test unknown provider, spoofing, stale revision, malformed/truncated chunks and real client artwork.
- **Core/session integration and unknown:** Hermes documents a Gamescope launcher that uses client resolution, runs nested Steam and relies on display layout; its container runs headless sway with audio/XWayland and optional Steam ([examples](https://github.com/MrOz59/Hermes/blob/main/docs/app_examples.md), [container README](https://github.com/MrOz59/Hermes/blob/main/packaging/container/README.md)). This is a session/display and deployment concern as well as an app target: qualify launch environment, session dimensions, compositor placement, process ownership and cleanup; do not make capture-driver internals part of a library API. Hermes notes service-launched Steam/Lutris needs desktop environment exported to the user manager ([getting started](https://github.com/MrOz59/Hermes/blob/main/docs/getting_started.md)). Availability and safe composition in Amaterasu remain unverified, not a proven missing core API.
- **Client authorization unknown:** Hermes reports Hestia enhanced endpoints require a paired client certificate and per-client permission ([README](https://github.com/MrOz59/Hermes)); this does not establish per-app ACLs. Amaterasu's catalog exports are scoped to configured initiating principals (`modules/catalog/src/pipeline.rs:322`) and identity exposes permission checks (`sdk/include/amaterasu_identity.h:38`). Determine Hermes actual per-app visibility and launch authorization from current primary source before specifying parity; if required, enforce the same client-aware decision for listing, artwork and launch, including revocation and forged identity tests.

Minimum qualification: import representative Hermes app records including duplicate/reordered names and unsupported fields; demonstrate safe repeat and failed scans; launch a detached/reparenting fixture and confirm ordered undo and fenced retry after ambiguous starts; retrieve real cover bytes with stale/revoked routes rejected; test per-app display profiles and Steam/Gamescope using a real Linux client and display; record actual host/container constraints and missing capabilities. Provider lifecycle assertions alone do not prove OS cleanup, and synthetic tests do not prove a playable stream.
