## Minimum extension and acceptance requirements

1. Extend generic provider presentation/discovery in a versioned, optional, bounded way: stable provider-scoped application ID, typed optional source/categories/tags/installation and last-played evidence, and declared capabilities. Keep source-specific filter policies in provider modules. Unknown fields/version transitions must not reinterpret identity or erase user data.
2. Make overrides a first-class catalog overlay for every authenticated attached provider, with revision conflict handling, explicit unset/inherit, durable detached/manual behavior and well-defined provider refresh versus user ownership. Verify collisions across providers, rename and manual edits, flag retention, mixed selection, incomplete scans, provider replacement and interrupted staged writes.
3. Route generic artwork by configured provider identity and opaque reference; validate revision, MIME, offsets, size, caller/initiator and cancellation. Add separately managed user uploads with precedence over fetched art, persistence on resync, replace/remove and safe cleanup. Test malformed chunks, stale revisions, 16 MiB bound, disconnected transfers and changed provider identity. External search and Playnite write-back require separate declared authority and explicit user intent.
4. Preserve lifecycle identity/incarnation and operation IDs through launch, lookup, stop, recovery and host cleanup. Test duplicate starts, stale incarnation, ambiguous outcomes, delayed starts, provider restart, partial snapshots and fail-closed cleanup. Real provider tests must demonstrate that provider evidence corresponds to game/process behavior.
5. Verify per-client/per-app precedence through actual launch and reconnect, including missing client, provider refresh and concurrent edits; expose only fields whose consumers actually honor them. UI should distinguish user overrides from provider metadata, current state from stale snapshots, unavailable art from absent art, and accepted launch from confirmed game exit.
6. Exercise real installed Playnite and extension on Windows, local Steam and Lutris on supported hosts, source updates, game focus, artwork, client streaming and end-to-end stop. Unit tests or source analysis alone cannot qualify any of those; `modules/playnite/README.md` explicitly says native Windows qualification and extension packaging remain outstanding.
