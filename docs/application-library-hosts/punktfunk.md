# Punktfunk library comparison

> Classification scope: read this audit with the [ecosystem plan](../application-library-ecosystem.md) and [boundary review](boundary-review.md). A generic API or core gap below describes the inspected current interfaces/composition. It does not require product behavior in the shell or a mandatory dependency on bundled Catalog, Launch, NVHTTP or transport. Library, protocol, networking and packet delivery implementations are intended to remain independently replaceable.

Audited 2026-10-31 against Amaterasu checkout `f8aa56337288632df64db1cca807dd3b0cd6beaa` (working tree had an unrelated dirty third-party submodule). This is source/document analysis, not an installed/runtime or hardware validation. Punktfunk's [official library documentation](https://docs.punktfunk.unom.io/docs/game-library), [plugin developer documentation](https://docs.punktfunk.unom.io/docs/developers/writing-plugins), and [source list](https://docs.punktfunk.unom.io/docs/plugins) are primary evidence. The [official GitHub repository](https://github.com/punktfunk/punktfunk) confirms the project and plugin-kit tree, but direct attempts to open its plugin-kit source and the documentation's canonical git.unom.io wire source returned cache misses; no Punktfunk source revision was independently pinned or code-level behavior verified. Claims below are documentation-confirmed and may differ from any particular released binary.

## Comparison and ownership

- **Discovery and identity — partial coverage; provider implementable, generic projection gap.** Punktfunk documents one plugin per launcher, host-side scans/watch loops, stable `provider:external_id` identifiers, and user-selected source enable/disable. Its catalog includes locally installed titles, while the install interface explicitly permits remote/not-yet-installed titles. The source list distinguishes Steam installed games and Playnite's whole library; don't infer that every launcher exposes all owned titles. Amaterasu can route selected discovery adapters (`modules/library/src/discovery.rs:9-29,104-126`) and import source-ID snapshot batches (`crates/module-sdk/src/application_library.rs:76-92,128-165`). The catalog allocates opaque `app-...` IDs (`modules/catalog/src/model.rs:1522-1558`); preserve provider identity/provenance as a mapping, not a requirement to expose Punktfunk's spelling. Current discovery pages expose only ID/name/optional art (`modules/library/src/discovery.rs:44-66`); no install availability or source enable state appears there. Scan formats, authentication, watch machinery, and launcher-specific identity belong inside providers. Confirm stable IDs across updates and restart, mapping collisions between two launchers, disable/re-enable behavior, and partial scan safety; do not assert ID persistence across delete/reimport without testing.
- **Query, metadata, user edits — shared contract gap.** Punktfunk documents custom entries, hide by entry or source, rich descriptions/platform/credits/genres/tags, source-managed fields, and user picks that survive sync. Amaterasu's catalog supports create/get/update/delete, list/search, revision checking and restricted provider override updates (`modules/catalog/src/protocol.rs:7-63,164-202,215-295`), but its exported library SDK lists/resolves only ID/name (`crates/module-sdk/src/application_library.rs:17-70`); catalog entry has description/tags and many config fields but no corresponding full metadata model (`modules/catalog/src/model.rs:12-76`). Provider-owned launch rows reject general update (`modules/catalog/src/protocol.rs:245-260`). Add a versioned, bounded metadata/provenance and user-overlay contract with explicitly defined precedence and persistent visibility; add useful search/filter/pagination to the consumer-facing route. Keep source metadata fetch/matching provider-owned. Any cross-provider enrichment policy and overlay durability are shared-library responsibilities, not assumptions that each source must rewrite one another's data.
- **Art — partial, generic API/core gap.** Punktfunk documents portrait/hero/header/logo, ordered metadata sources, search/pinning, explicit user selection, provenance and fills for missing values. Amaterasu has bounded discovery art references and SDK provider artwork methods (`modules/library/src/discovery.rs:44-56`, `crates/module-sdk/src/application_library/provider_adapter.rs:20-28,73-79`), but catalog artwork is a closed Steam/Lutris/Playnite enum (`modules/catalog/src/model.rs:94-102`), and generic discovery does not enable generic catalog artwork routing (`docs/application-library-provider-configuration.md:168-173`). Design provider-neutral revisioned art slots and routing, bounded transfers, invalidation, provenance and user overrides; do not expose arbitrary host file paths to clients. Verify capability negotiation and source removal fallback.
- **Provisioning/actions — generic API and orchestration gap.** Punktfunk's developer documentation specifies missing/installed state, async start, pause, cancel, uninstall, progress, stall handling, launch waiting, and re-reconciliation; download and cleanup of downloaded files belong to the plugin, with saves retained. Amaterasu's selected provider adapter dispatches discovery, artwork, identity and launch/lookup/recover-stop/stop only (`crates/module-sdk/src/application_library/provider_adapter.rs:18-51`); there is no generic install/progress/action surface in that contract, and `Entry` requires a launch target (`modules/catalog/src/model.rs:12-76`). Define optional per-entry capabilities and an operation ID-based asynchronous provision lifecycle with bounded progress/state/error, cancellation and recovery semantics, explicit availability/launchability, and safe provider-specific uninstall scope. A shared orchestration path must wait for confirmed readiness before launch, handle failures, stalls, restart/reconciliation and races, and expose meaningful state to clients. Do not make launcher binaries, stores, transfer engines or their credentials core concepts.
- **Events — gap/unknown.** Punktfunk documents file watching and progress reports plus `game.launching` holds. Amaterasu snapshots provide revision and controlled completion (`crates/module-sdk/src/application_library.rs:8-11,128-165`), but no event subscription appears in the audited library facade and adapter (`crates/module-sdk/src/application_library.rs:32-44`; `provider_adapter.rs:18-51`). Define versioned change/progress notifications or equivalent resumable cursor and an authoritative requery path, including missed updates, reconnect and stale revisions. This is a scoped finding about these interfaces, not a claim that the whole runtime lacks events.
- **Launch/cleanup — existing foundation, qualification required.** Punktfunk documents ID-only client launch, process detection, end-game ownership, pre-launch plugin holds and exit/session behavior. Amaterasu resolves an opaque provider target with importer/source binding and has launch lifecycle actions, fencing and retirement evidence (`modules/catalog/src/model.rs:967-982`; `docs/application-library-provider-configuration.md:175-190`; `crates/module-sdk/src/application_library/provider_lifecycle.rs:70-126`). Operator-selected mappings and real providers must supply authorization, durable reconciliation and effects; an SDK fixture is synthetic and does not prove actual applications or restart cleanup (`docs/application-library-provider-configuration.md:3-9,49-55`). The cited document says provider retirement evidence is trusted, not OS-verified. Confirm with real launchers, cancellation/disconnect, process handoff, reattach and restart, including client ownership rules; a generic hold and per-client end-game parity remain unproven in this audit.
- **Projection and client behavior — shared API and client gap.** Punktfunk describes hiding, launcher rows, display of missing-title installation, native-client library, Moonlight exclusion of unlaunchable titles, and play stats; source docs do not imply GameStream supports Punktfunk's richer download interface. Amaterasu library export intentionally hides launch metadata and supplies `id`/`name` (`modules/catalog/src/protocol.rs:24-31,164-175`, `crates/module-sdk/src/application_library.rs:46-70`), a useful safe basis, but it cannot currently communicate those richer states. Add capability-aware native projection and preserve legacy protocol compatibility: never advertise a nonlaunchable item as immediately playable in a client that cannot provision it. Stats and profile attribution need independent requirements and validation; no claim of absence across all Amaterasu modules is made here.

## Minimal acceptance checks

1. Two independently implemented providers publish overlapping external IDs without collision; snapshot updates, incomplete scans, restart and disable/re-enable preserve correct identity and user overlays. Explicitly exercise staged and incremental failure semantics and revision conflict recovery.
2. Query/filter/page returns bounded, deterministic results under mutation; permissions and stale cursors are handled; manual entries and provider entries maintain source provenance and user edits without exposing launch commands.
3. Generic provider art supports multiple optional slots, safe bounded retrieval and revisions; user choice persists over provider resync and fallback after source withdrawal is deterministic.
4. A missing remote item can appear with capability and availability, begin asynchronous provision, report bounded progress, pause/resume/cancel where offered and reconcile after provider/host restart. Refusal, timeout, stall, duplicate requests, cancellation races and provider removal cannot silently launch or delete saves. Uninstall is explicitly authorized and limited to provider-owned material.
5. Client launches only an authorized opaque catalog ID; a missing item starts only after confirmed readiness. Exercise operation correlation, launch/stop/recover fencing, lost replies, provider incarnation changes and process handoff with real provider implementations. Cleanup is reported unconfirmed when proof is unavailable.
6. Event disconnect/reconnect recovers via revisioned requery; clients show correct state and older clients get a safe launchable-only projection. Validate source-managed fields, hidden entries/sources and edit/art precedence end to end.

Native modules are trusted code: broker grants and SDK adapter checks route authority but do not sandbox provider code (`crates/module-sdk/src/application_library.rs:1-6`; `provider_adapter.rs:1-7`). Punktfunk's independently documented sandbox design is not an Amaterasu security property.
