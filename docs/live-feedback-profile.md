# Live feedback startup profile

Live feedback is opt-in. Trusted startup sets `RuntimeConfig.live_feedback` to the six distinct provider principals for the protocol, pairing authority, stream owner, input provider, lifecycle provider and control transport. If the host-configuration service is installed, the profile must also name `host_configuration_owner`. Omitting the profile retains the prior disabled source-join behavior and does not grant an API or a client capability.

The broker validates explicit service selections and grants before it starts. It requires the selected NVHTTP, pairing administration and pairing-effects, State, stream-session, input, lifecycle and control broker routes. Pairing administration, pairing-effects and the native identity factory must use the same selected pairing principal. The native identity selection uses `amaterasu.identity.native/1`; the shared SDK adapter registers and binds that typed contract. When this profile is absent, existing legacy identity registration and binding remain unchanged. The native control route must select the same control provider as the selected broker route and the standard control contract; a replacement service alias is supported. The selected settings must agree on the protocol owner, stream owner, input consumer, lifecycle input provider, feedback source service and whole-control retirement service. Input observation, scoped retirement and owner restart recovery must be enabled together. Lifecycle must authorize the selected callers and operations; the control service must admit the selected stream owner. The pairing authority must select at least one valid feedback policy and retain the existing per-client capability and permission checks.

If host configuration is present, it must select pairing as its effect authority, pairing must select that configuration principal, and both sides must have the required calls. A profile with an installed but unfenced host-configuration provider is rejected. If host configuration is absent, the pairing host-configuration marker and configuration owner must also be absent. Each component's own settings and provider contract validation still apply; selecting a contract or declaring a capability is not proof that a replacement implements retirement correctly.

After validating this topology, the broker injects a private `live_feedback_authorized` setting into only the selected protocol, pairing and stream owners. Package-provided values for this setting are rejected. Normal module ABI entry points then allow the selected feedback path; no qualification-only entry point is required. Admission remains bound to authenticated TLS ownership, the current pairing snapshot, the exact lifecycle/source/device generations and a selected feedback capability. Client permissions are not expanded by this startup profile.

On revocation or teardown, the authority fences new admissions. The stream owner retires the whole selected control transport, waits for its local worker and queue drain, and acknowledges only the corresponding receipt. Already sent network packets cannot be recalled. Restart recovery requires a new owner epoch and verified old-owner retirement; lost or uncertain cleanup remains closed.

This profile does not select or recover the optional durable generic protocol journal. It rejects a concurrently selected generic broker effect authority until a reviewed composition can coordinate both fences. A fresh feedback-only composition does not require it. If a previous historical profile may have admitted work, trusted migration must retain its authority and State selection until its original owners have retired and external cleanup is verified. Removing a profile, a provider name or an in-memory entry is not cleanup evidence. Do not silently enable a new route that can touch an unresolved resource. This document does not claim automatic migration across historical profiles.
