# KMS capture provider

This provider reads active physical DRM primary-plane framebuffers into owned BGRA CPU frames. It opens primary DRM nodes only for metadata, imports the selected framebuffer through DMA-BUF and EGL, and reads pixels through GLES. It never performs a modeset or requests DRM master. A stream reports `frame_readback_verified: false` until an actual framebuffer read succeeds. It returns the primary-plane image, not a promise of final display composition: cursor and overlay planes and the CRTC color pipeline are not captured. Outputs are rejected when standard plane properties do not prove an unscaled, unrotated full-output primary plane.

`native_supported` reports whether this build linked libdrm, GBM, EGL, and GLES. `available` reports whether the process can inspect and export an active, supported primary framebuffer. Each output reports `framebuffer_export_supported` after the metadata and PRIME export preflight. The selected EGL import is checked on stream open, and `frame_readback_verified` stays false until an actual frame read succeeds. Presentation timestamps are local monotonic acquisition times. This provider does not implement the Vibeshine DRM private presentation ioctls or its restricted helper, so it cannot capture managed Vibeshine virtual outputs with event-driven timestamps.

Framebuffer access is permission-sensitive. The module only uses capabilities already permitted to its process, and returns a specific unavailable reason when DRM framebuffer export is denied. It does not add capabilities or install helpers. Output and framebuffer changes are revalidated during reads; a mode change fails the read with an error instead of returning stale or synthetic pixels.

Host shutdown rejects new opens while existing consumers finish. Module quiescence drops the owned native capture sessions before reporting ready; a busy controller remains pending and a poisoned controller reports an error. Native destruction is synchronous, and its EGL destruction results are not propagated, so a ready response does not prove that every native resource retired. EGL context binding is thread-specific, while open, read, and close can run on different calling threads; a session left current on another thread can prevent a later bind or defer destruction. The adapter also cannot report failure to restore the calling thread's selected EGL API. EGL display termination can affect resources sharing that display. The provider needs an isolated, owned execution and retirement boundary to address these limitations. Isolated ownership tests do not prove that GPU driver operations are interruptible.
